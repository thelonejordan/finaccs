# Main Section

## Overview

The revamped extraction pipeline is designed to be **format-agnostic** and **data-agnostic**. It makes no presumptions about:
- The type of files being processed (PDF, XLSX, CSV, TXT, images, etc.)
- Whether files are password-protected
- The kind of data being extracted (transactions, metadata, summaries, or any future data type)

This flexibility allows the same pipeline to support new views and data types without architectural changes.

---

## Core Concepts

### 1. File Sources

Files are organized by domain:
- `bank_accs/data/` - Bank account statement files
- `credit_cards/data/` - Credit card statement files

The system discovers files via a **refresh** mechanism that scans these directories and surfaces new files in the UI.

### 2. Extraction Pipeline Stages

```
FILE DISCOVERY → REGISTRATION → EXTRACTION RUN → TRANSFORMATION → CONSUMPTION
      │               │               │                │               │
      ↓               ↓               ↓                ↓               ↓
   Scan dir      SourceFile      Extraction     DataSource        Views/
   for files     (blob+meta)        +           Artifact          Loaders
                                ExtractionArtifacts
```

### 3. Key Entities

#### SourceFile
The raw file as uploaded/discovered. Stores:
- File blob (compressed)
- File hash (for deduplication)
- Mime type
- Password (if encrypted, user can add/update)
- Domain association (bank/credit card)
- Assigned extractor (manual selection or auto-select)
- Extraction status: `not_extracted` | `extracted`
- Hidden flag: for UI list organization (see List Visibility Toggle)

#### Extractor
A pluggable component that:
- Accepts a SourceFile
- Produces an **Extraction** containing one or more **ExtractionArtifacts**
- Defines the artifact types it can produce
- Assigns optional artifact keys for disambiguation
- Assigns `data_source_target` and `transformer` for each artifact

#### Extraction
A record of a single extraction run:
- Has a unique `extraction_id`
- Links a SourceFile to an Extractor
- Contains one or more ExtractionArtifacts
- Tracks extraction status and timestamp
- Hidden flag: for UI list organization (see List Visibility Toggle)

#### ExtractionArtifact
A discrete piece of extracted data produced by an Extractor:
- Has a unique `artifact_id`
- Has an `artifact_type` (defined by the Extractor)
- Has an optional `artifact_key` (for disambiguation, e.g., card numbers)
- Has a `content_format` (CSV, JSON, TXT, etc.)
- Has a `data_source_target` (which DataSource this maps to, can be null)
- Has a `transformer` (converts artifact to DataSource spec format)
- Is independently consumable
- Transformation status: `not_transformed` | `transformed` (only for artifacts with data_source_target)
- Can be transformed individually (user controls when to transform each artifact)

#### DataSource
A destination for loading artifacts into UI views:
- Has a unique `data_source_target` identifier (e.g., `bank_account_transactions`, `credit_card_transactions`)
- Has a **Spec** defining the data format it accepts
- Displayed in the Console Page's Data Source Section
- Multiple ExtractionArtifacts can have the same `data_source_target`

#### Transformer
Converts artifact content to DataSource spec format:
- Takes raw ExtractionArtifact as input
- Outputs a **DataSourceArtifact** conforming to DataSource spec
- Assigned by the Extractor to each artifact
- Can be null if artifact already conforms to spec

#### DataSourceArtifact
The result of transforming an ExtractionArtifact:
- Adheres to the DataSource spec
- Links back to the source ExtractionArtifact for provenance
- Links to domain entity based on `data_source_target`:
  - `bank_account_transactions` → linked to a **BankAccount**
  - `credit_card_transactions` → linked to a **CreditCard**
- Loading status: `unloaded` | `loaded` (UI displays "Ready to load" for unloaded)
- Enabled/disabled flag (default: enabled when loaded)
  - Enabled: data is shown in the view
  - Disabled: data stays loaded but not shown in the view
- Hidden flag: for UI list organization (see List Visibility Toggle)
- Appears in Data Source Page when unloaded (shown as "Ready to load")

#### DataSourceLoader
Handles loading/unloading of DataSourceArtifacts:
- Loads DataSourceArtifact content into domain tables (Transaction, CreditCardTransaction)
- Unloads (deletes) data when DataSourceArtifact is deleted
- Cleans up associated DataSourceArtifacts when an Extraction is deleted
- Manages post-load transaction data on unload/reload (see below)
- Ensures data integrity across the pipeline

#### Post-Load Transaction Data
After loading, transactions can have additional data attached:

**Types of post-load data:**
- **Links**:
  - Self Transfers (bank account ↔ bank account)
  - Credit Card Payment Links (bank account ↔ credit card)
- **Tags**: User-assigned categories/labels
- **Inconsistency markers**: e.g., marked as duplicate
- **Other metadata**: Any data added to transactions post-load

**Behavior on unload/reload:**
- **On Unload**: Post-load data is removed (links broken, tags removed, etc.)
- **On Reload**: Reapply optimistically
  - If the original state can be restored, restore it
  - If the data was modified while unloaded (e.g., counterpart linked to something else), respect the new state
  - Example: If txn A was linked to txn B, then unloaded, and txn B got linked to txn C, do not restore A↔B link on reload

#### List Visibility Toggle
A UI organization feature to help manage clutter in list views. Applies to:
- SourceFile list
- Extraction list
- DataSourceArtifact list

**How it works:**
- Each entry has a `hidden` flag (default: false)
- User can toggle visibility on/off for any entry
- A dropdown at the top of each list switches between:
  - **Show visible** (default): displays entries where `hidden = false`
  - **Show hidden**: displays entries where `hidden = true`
  - **Show all**: displays all entries regardless of `hidden` flag

**Important distinctions:**
| Feature | Purpose | Affects Data/View? |
|---------|---------|-------------------|
| `hidden` flag | UI clutter management | No - purely cosmetic, hides entry from list |
| `disabled` flag (DataSourceArtifact only) | Exclude from view calculations | Yes - data stays loaded but excluded from view |

#### Bulk Select & Update
For managing large numbers of entries efficiently:

**Applies to:**
- SourceFile list
- Extraction list (and its artifacts)
- DataSourceArtifact list

**Features:**
- Checkbox per entry for individual selection
- "Select All" / "Deselect All" button
- Bulk action dropdown/buttons for batch operations

**SourceFile bulk actions:**
- Assign password (to selected files)
- Assign extractor
- Extract
- Hide / Unhide

**Extraction bulk actions:**
- Transform All (transforms all transformable artifacts in selected extractions)
- Hide / Unhide
- Delete

**Extraction artifact selection behavior:**
- Selecting an extraction auto-selects all its artifacts for transformation
- Individual artifacts can also be selected/deselected independently
- Allows fine-grained control: select extraction → deselect specific artifacts

**DataSourceArtifact bulk actions:**
- Assign BankAccount / CreditCard
- Load
- Unload / Delete
- Enable / Disable
- Hide / Unhide

**Smart bulk updates:**
Operations are applied intelligently - skip entries where the action doesn't apply:
- If file is already hidden → skip when hiding
- If file is not password-protected → skip when assigning passwords
- If artifact is already loaded → skip when loading
- If artifact is already disabled → skip when disabling
- If artifact is already transformed → skip when transforming

### Extraction Model

An **Extraction** represents a single run of an Extractor on a SourceFile:

```python
class Extraction:
    """
    Record of a single extraction run.
    Groups all artifacts produced from one SourceFile by one Extractor.
    """
    extraction_id: str                    # extraction_xxxxxxxx (unique)
    source_file: SourceFile               # Input file
    extractor_name: str                   # Which extractor was used
    status: str                           # pending, completed, error
    extracted_at: datetime                # When extraction ran
    artifacts: List[ExtractionArtifact]   # Output artifacts
    hidden: bool                          # Default: False. For UI list organization
```

### Extractor Interface

```python
class Extractor:
    """
    Base class for all extractors.
    Each extractor defines its own ArtifactType enum.
    """
    name: str                          # e.g., 'icici_cc_pdf'

    class ArtifactType(Enum):
        """
        Each extractor defines its own artifact types.
        This is an example - each extractor subclass defines its own.
        """
        pass

    def extract(self, source_file: SourceFile) -> Extraction:
        """
        Run extraction on a source file.
        Returns an Extraction containing one or more ExtractionArtifacts.
        """
        pass


# Example: ICICI Credit Card PDF Extractor
class ICICICreditCardPDFExtractor(Extractor):
    name = 'icici_cc_pdf'

    class ArtifactType(Enum):
        TRANSACTIONS = 'transactions'
        EMI = 'emi'
        METADATA = 'metadata'


# Example: SBI PDF Extractor
class SBIPDFExtractor(Extractor):
    name = 'sbi_pdf'

    class ArtifactType(Enum):
        TRANSACTIONS = 'transactions'
```

### ExtractionArtifact Model

```python
class ExtractionArtifact:
    """
    A discrete, typed piece of extracted data.
    The pipeline makes NO assumptions about artifact content.
    """
    artifact_id: str                    # ext_artifact_xxxxxxxx (unique)
    artifact_type: Extractor.ArtifactType  # Enum defined by the extractor
    artifact_key: str                   # Optional key for disambiguation (e.g., card number)
    content_format: str                 # 'csv', 'json', 'txt', 'binary'
    content: bytes                      # gzip(data)

    # DataSource mapping
    data_source_target: str             # Target DataSource name (nullable)
    transformer: str                    # Transformer to apply before loading (nullable)
    transformation_status: str          # 'not_transformed' | 'transformed' (if data_source_target is set)

    # Provenance
    extraction: Extraction              # Parent extraction run
```

### DataSource Registry

```python
class DataSource:
    """
    A destination for artifact data.
    Each DataSource defines what data format it accepts.
    """
    data_source_target: str    # e.g., 'bank_account_transactions'
    spec: DataSourceSpec       # Schema/format specification

class DataSourceSpec:
    """
    Defines the expected format for a DataSource.
    """
    columns: List[str]         # Required columns for CSV
    column_types: Dict         # Column type definitions
    # ... additional validation rules
```

### Transformer Registry

```python
class Transformer:
    """
    Converts ExtractionArtifact content to DataSource spec format.
    """
    name: str                  # e.g., 'icici_cc_to_transactions'
    input_format: str          # Expected input format
    output_data_source: str    # Target DataSource

    def transform(self, artifact: ExtractionArtifact) -> DataSourceArtifact:
        """
        Transform ExtractionArtifact content to DataSource spec format.
        Returns a DataSourceArtifact ready for loading.
        """
        pass
```

### DataSourceArtifact Model

```python
class DataSourceArtifact:
    """
    The result of transforming an ExtractionArtifact.
    Adheres to a DataSource spec and is ready for loading.
    """
    artifact_id: str                       # ds_artifact_xxxxxxxx (unique)
    data_source_target: str                # Target DataSource (e.g., 'bank_account_transactions')
    content: bytes                         # gzip(data) - conforms to DataSource spec
    status: str                            # 'unloaded' | 'loaded'
    disabled: bool                         # Default: False. If True, data not shown in view
    hidden: bool                           # Default: False. For UI list organization

    # Domain entity link (based on data_source_target)
    bank_account: BankAccount              # If data_source_target = 'bank_account_transactions'
    credit_card: CreditCard                # If data_source_target = 'credit_card_transactions'

    # Provenance
    source_artifact: ExtractionArtifact    # The artifact this was transformed from
    transformer: str                       # Which transformer was used
    transformed_at: datetime               # When transformation occurred
```

## Consumption Layer

ExtractionArtifacts flow to **DataSources** which power UI views. The extraction pipeline assigns each artifact a `data_source_target` and `transformer`.

### DataSources

Each DataSource has a `data_source_target` identifier and represents a view in the Console Page:

| data_source_target | UI View | Spec |
|--------------------|---------|------|
| `bank_account_transactions` | Bank Accounts Transactions | date, narration, debit, credit, balance |
| `credit_card_transactions` | Credit Card Transactions | date, description, amount, intl_amount, currency |
| (future) | EMI Schedule | date, description, amount, tenure |

### Loading Process

1. User selects ExtractionArtifacts to load in Console Page
2. For each ExtractionArtifact with `data_source_target`:
   - Apply `transformer` to create a **DataSourceArtifact**
   - Validate DataSourceArtifact against DataSource spec
   - **Link DataSourceArtifact to domain entity** based on `data_source_target`:
     - `bank_account_transactions` → link to selected **BankAccount**
     - `credit_card_transactions` → link to selected **CreditCard**
   - Insert DataSourceArtifact content into domain table (Transaction, CreditCardTransaction, etc.)
3. ExtractionArtifacts with null `data_source_target` are viewable but not loadable
4. DataSourceArtifacts are persisted for audit trail and re-loading

## Design Principles

1. **No Data Presumptions** - The pipeline extracts "artifacts" without assuming what they contain
2. **Pluggable Extractors** - New file formats are supported by registering new extractors
3. **Typed Artifacts** - Artifacts have types defined by their extractor, but the pipeline doesn't interpret them
4. **Keyed Artifacts** - Artifacts can have optional keys for disambiguation (e.g., multiple cards in one PDF)
5. **Grouped by Extraction** - All artifacts from one extraction run are grouped under a single Extraction record
6. **DataSource Targeting** - Extractors assign artifacts to DataSources (or null if no mapping exists)
7. **Transformer Decoupling** - Transformation logic is separate from extraction logic
8. **Full Provenance** - Every artifact traces back to its extraction, source file, and extractor
